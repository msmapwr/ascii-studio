# Charloom 路线图

## 1.0：双语、个性化与桌面全功能 CLI

此目标按 Large 管理，仅发布 alpha／beta／rc；用户明确授权之前不发布正式 1.0.0。0.9.0 已正式交付，下方 0.9 路线保留为已完成主线记录。

1. **共享服务与 CLI 基础（alpha.1）**：提取无 WinUI 依赖的应用层；完整中英文逐级帮助、转换／导出／项目／字体／工具／加密／设置／批处理。首版明确公布已实现与缺口，见 [完整 CLI 覆盖表](CLI.md)。
2. **编辑与工作区一致性**：alpha.2 已完成项目旁状态文件、100 步／64 MB 持久撤销、Unicode 行列／矩形选区、基础编辑动作、多项目 active 列表、恢复与最近项目、工具显式应用。alpha.3 已完成候选结果管理；alpha.6 已补齐显式文本剪贴板、可撤销粘贴与图片读取；几何历史继续补齐。
3. **双语与个性化**：GUI 中文／英文资源、CLI 领域错误本地化＋固定错误码；界面与作品字体分离、偏好持久化／导入导出／重置、设置搜索收藏、配方和平台助手、教程。动画遵循 Windows 动画设置，减少动态效果时保留直接反馈，主题切换约 200 ms。
4. **预览与交付验收**：CLI TXT／ANSI／PNG／HTML 预览、缩放适应、分页与对比，全部 GUI 功能逐项映射并自动验证；双架构同包、完整 help 与兼容性测试。只有覆盖矩阵全部验收后才宣称桌面全功能 CLI。

每个 Medium 再拆 Small；命令、配置、项目与默认参数优先级及安全策略沿用已确认的 24 项选择。未冻结功能才进入覆盖矩阵；MCP／API 和快速 UI 测试仍仅规划，不在本轮实现。

## 产品定位

**Windows 原生、离线、高质量 ASCII / ANSI 创作工具。**

创作主线：导入图片或文字 → 调整转换质量 → 编辑与比较 → 保存可继续创作的项目 → 导出作品。
每个新功能都先回答：它是否强化这个定位？不能直接改善上述主线的能力暂不进入 0.9。

## alpha.8：核心收敛与可维护性

- 提取图片、文字转换 Controller，独立管理取消、过期结果、预览与项目快照。
- 算法明确划分采样、颜色调整、边缘增强、抖动、字符映射；保留旧项目与输出兼容。
- 核心检查迁至 xUnit，按领域组织，CI 输出独立测试结果。
- README 先展示真实转换样例、软件界面与操作 GIF，再提供下载和开发说明。
- 历史迭代文档归档；保留路线、架构、格式与资源边界等长期文档。

## alpha.9：主线稳定性与交付

- 用户确认新增 25 种字符处理方法，作为字符作品的编码、文本互通、压缩与校验工具；采用严格编码、可选 BOM、Hex／Base64 字节表示及 4 MB 解压预算。不扩大到完整序列化平台。

- 图片／文字／ANSI 的异常输入、取消竞争、项目恢复和手工编辑保护回归。
- 性能和内存预算验证；继续收薄页面中的输入读取、项目恢复与字体库呈现。
- 导出结果、色彩、透明度、Unicode 对齐、字体缺失和旧格式迁移逐项验收。
- 紧凑窗口、DPI、主题、键盘和辅助功能 UI 验收；安装／便携包和 CI 交付检查。
- 优先修复已发现的问题，不为凑版本增加新模块；未完成验收不得宣称完成。

## 后续候选：AI 接口与快速 UI 测试（仅规划）

以下两项已纳入计划，**本轮不开发、不增加依赖，也不纳入 alpha.8／alpha.9 当前验收**。
实施时间与发布版本待后续确认；两项都服务于现有 ASCII / ANSI 创作主线。

### 1. 供 AI 调用的 MCP / API

- 目标：让 AI 工具以结构化方式处理图片、文字和字符作品，复用应用的转换能力。
- 接口范围：查询支持能力与参数、图片／文字转换、读取和编辑结果、打开／保存项目、导出作品；支持任务状态、取消和进度。
- 架构：独立应用服务提供统一命令契约，GUI、API 和 MCP 共用 Controller／算法管线；不另写一套转换实现。
- 数据：版本化请求／响应与参数定义，返回文本、颜色网格、作品元数据或导出文件引用；明确错误码、资源上限及兼容策略。
- 连接：优先规划本地 MCP stdio；如提供 HTTP API，默认限本机并按授权启用。文件访问限定授权目录，覆盖和结果替换遵循现有编辑保护。
- 验收：AI 客户端可完成“输入 → 转换 → 调整 → 导出”；结果与 GUI 同参数一致，取消、错误和大输入均有可验证响应。

### 2. 快速 UI 测试入口

- 目标：Agent 能快捷准备场景、执行操作和读取界面状态，减少耗时的逐项鼠标点击与固定等待。
- 测试入口：规划独立测试模式，直接加载隔离项目／设置，导航到指定页面、设置参数、执行真实应用命令，并等待明确的“界面／转换空闲”信号。
- 状态查询：按稳定 AutomationId 获取控件值、可见性、启用状态、错误、活动项目及结果摘要；支持一次提交一组操作与断言。
- UI 交互：优先 UI Automation 的 Invoke／Value 等语义操作；必要时通过测试桥接调度到 UI 线程，走与用户操作相同的命令路径。
- 验证分层：Controller 与算法用 xUnit；快速 UI 测试检查实际控件状态、绑定和布局快照；滚轮、键盘、拖放、DPI 等保留少量真实输入回归。
- 隔离与报告：专用数据目录和固定素材，不修改个人会话；自动记录耗时、断言、错误和失败截图。测试入口默认关闭，不作为普通用户操作入口。
- 验收：核心创作流程可用一条命令批量验收，无需人工连续点击；仍检查真实 WinUI 页面，不能只用业务测试代替 UI 验收。

## 冻结范围

动画转换与编辑、视频、摄像头、3D 导入及操控全部冻结，不开发、不引入依赖、不计入 0.9 验收。
复杂绘画、图层、拼贴和扩展素材平台亦不作为当前承诺；已有生成器和工具保留兼容性维护。
冻结项以后只有重新确认产品价值、成本及边界后才进入路线。
