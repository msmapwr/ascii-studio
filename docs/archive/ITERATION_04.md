# 0.3.0 · DPI 与响应式布局

## 范围与决定

Medium，分为 DPI 声明、窗口尺寸、工作区重排、弹层适配、首页适配、窗口记忆与验证等 Small。用户已确认：顶部输入按钮、最小 480×480 DIP、窄屏隐藏欢迎画、必要时弹层内部滚动、记住窗口位置和尺寸。沿用 microsoft/win-dev-skills。

原进程由 WinApp UI 识别为 unaware。本版清单启用 PerMonitorV2；运行验证窗口 DPI=144、scale=1.5，且 Win32 DPI context 与 PerMonitorV2 常量相等。初始窗口按实际 DPI 换算物理像素并居中。

导航使用 Auto 模式。工作区可用宽度低于 760 DIP 或高度低于 420 DIP 时，输入区迁入顶部按钮弹层，宽高恢复后回到原位置。控件和结果实例保留。设置弹层限宽、限高，密集字段在窄宽度下改单列。首页卡片按可用宽度排为 1/2/3 列。短窗口压缩标题区。

字体按最新要求放在转换方式下方。FIGlet 模式显示 FIGlet 字体，系统模式显示系统字体；系统模式列数留在顶部尺寸菜单。

## 验证

- Debug 构建、编译类型检查、WinUI 分析器：0 警告、0 错误。
- 修改 C# 文件的 dotnet format 验证通过。
- 核心转换检查 8/8 通过。
- 最终完整 UI 批次 10/11 通过，唯一失败是首页 Border 容器没有 UIA peer。后续修正为检查三个真实创作按钮和可见卡片宽度，独立测试实例的首页专项通过。其余 10 项已通过，包括窄屏文字生成、主要字体入口、分辨率单列、宽窄切换保持结果、窗口尺寸与位置重启恢复。
- 早期批次发现测试调用者 DPI 虚拟化、最大化还原时序、收起导航的定位和启动等待问题；脚本修正这些前置条件，未删除有效功能断言。屏幕外控件的 UIA 坐标不用于列位置断言。
- 查看宽屏、最小窗口、输入弹层、分辨率、文字与首页截图，记录在 `artifacts/ui-responsive/`。
- 当前仅验证本机 150% 缩放。没有声称完成 100%/200% 或混合 DPI 多屏验证；本轮没有更新已生成的旧 MSIX。

窗口位置独立存于本地 window.json；正常窗口记录尺寸（DIP）和位置（物理像素），保留最大化状态。无效设置回退默认值；退出时原子写入小型文件，不覆盖主题和项目设置。

## 审查

使用原生导航、输入按钮和 Flyout；迁移控件前解除旧父级，避免重复挂载。XamlRoot 监听随弹层关闭、结果区卸载解除。主窗口尺寸约束随 DPI 改变更新。保留现有程序式 UI / MVVM、国际化和部分无障碍技术债务，本轮未宣称完整解决。
