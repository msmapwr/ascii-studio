# AsciiStudio：基于 asciiart.eu 的完整功能计划

版本：2.0；调研日期：2026-09-30；状态：待实现的产品需求与交付方案。

本文件是当前范围的主计划，取代旧计划中的功能范围与发布分期。此前环境检查事实仍有效。实现、性能与素材数量均须经过验收，本文不代表程序已经具备这些能力。

## 1. 目标、范围与证据规则

将 asciiart.eu 的创作、转换、生成、查看、分析、动画及图库能力组织成高质量 WinUI 3 桌面应用。用户已明确排除：**游戏、历史档案、会员系统**。本地收藏、保存和作品集保留；大尺寸、全屏、高级导出等在网站上由 Premium 解锁的工具能力保留为普通桌面功能。

排除模块包括小游戏及游戏文章、Usenet/历史合集/历史文献与历史时间线、注册登录/密码恢复/个人在线资料/订阅/支付/会员权益。迷宫的第一人称漫游作为生成器的交互预览保留，不设置游戏关卡、成绩或排行榜。

默认决策：WinUI 3；中文/英文；本地离线处理；项目名称暂为 AsciiStudio；支持 x64，完整发布提供 ARM64；不引入账户、联网点赞计数或公共发布平台。生成和编辑内容保存在本机。

调研依据为网站公开页面、说明、发布记录及公开 HTML 表单选项。动态绘画界面、部分弹窗和受限制页面尚未完成实际操作验证。证据分三级：

- **V：已核实**，公开页面或表单存在该功能。说明存在不代表已验证所有运行行为。
- **D：网站声明**，功能介绍或未来计划有说明，但本次未验证实际操作。
- **U：待核实**，选项名称、数量或行为不完整；必须进入调研清单，完成前不能宣称全面对齐。

所有需求 ID 都是计划项，初始实现状态为“未开始”。研发顺序只决定先后，不删减最终范围。

## 3. 信息架构与主流程

左侧主导航控制为七组：**首页、转换、绘画、生成器、动画、作品库、文本工具**；设置和帮助置于底部。各组内部使用子导航，避免把 17 个工具和 14 个动画同时堆在主菜单。

- 首页：最近项目、收藏工具、继续编辑、示例、一键创建。
- 转换：图片、文字、摄像头、3D；ANSI 查看器可从转换与作品库进入。
- 绘画：统一字符画布与素材面板。
- 生成器：边框、分隔线、迷宫、夜空、图案。
- 动画：动画目录、实时参数、捕获与导出。
- 作品库：分类、搜索、收藏、个人作品集、边框/分隔线/图案/单行素材。
- 文本工具：艺术分析、ASCII 校验、大小写转换、字符统计、清理、词统计。

标准工作流：导入或输入 → 快速预览 → 调整 → 发送到绘画/分析/校验 → 保存项目或导出。工具间传递同一文档快照，保留字符、颜色、尺寸、来源、作者和参数；不能通过中间纯文本传递丢失彩色结果。

布局：顶部命令栏，中间可缩放工作区，右侧参数，底部状态；原图与结果可并排或切换。窄窗口采用页签，支持面板收起、全屏、键盘导航和高对比度。耗时工作支持进度、取消、重试；失败保留最后成功结果。

## 13. 技术架构

建议 .NET 10 + WinUI 3 + 受支持的 Windows App SDK Stable；具体包版本与原生渲染依赖在环境阶段固定。当前旧骨架升级到真实可运行模板后再扩大工程。

```text
App.WinUI         页面、样式、MVVM、快捷键、生命周期、能力检测
Application       任务调度、工具联动、历史、项目、批量、导出用例
Core              网格、转换、生成、分析、校验、动画时间轴、参数模型
Rendering         字体测量、文字/位图/混合、颜色、3D 到字符、绘画显示
Infrastructure    图片/摄像头/模型/字体、ANSI、存储、素材、导出、系统适配
Cli               命令行
Tests             核心、集成、UI、视觉样本、性能基准
```

UI 不为每个字符创建独立控件。采用紧凑网格、可见区域绘制、缓冲池、分块处理、字体特征缓存、有界并发；长任务具备取消/进度。实时采集只处理最新帧，丢弃旧帧积压；参数更新以请求版本防止旧结果覆盖。

3D 场景与实时特效采用共享帧源接口，转换到统一字符网格。公式使用白名单表达式解析，模型资源定位受控。动画离线导出按照固定时间步长计算，与屏幕刷新频率分离。

字体、图标、图片解码、3D 解析和视频编码依赖均先做兼容性原型、固定版本并记录许可证。不复制原站脚本、绘画程序、游戏代码或专有实现；本计划的功能与算法独立开发。

## 14. 质量指标与验收体系

目标基准环境：Windows 11、6 核 CPU、16GB、SSD、1080p；须固定实际机器型号、版本、功耗配置与输入。以下均为目标，不是当前已测结果。

| 类别 | 目标/规则 | 证据 |
| --- | --- | --- |
| 可用性 | 所有纳入范围的操作都有实现、反馈、错误处理与帮助 | 需求 ID 对应演示和结果记录 |
| 响应 | 操作可见反馈 ≤100ms；常规 120 列转换+显示 p95 ≤300ms，不含首次解码 | 固定图集与分阶段计时 |

| 大尺寸 | 500×300 字符图案可预览/导出，预算超限有提示；大型文本有界内存 | 峰值与压力记录 |
| 稳定性 | 100 次开关/转换和 30 分钟实时运行，无崩溃、资源泄漏或持续增长 | 压力报告与设备释放检查 |

| 数据安全 | 保存原子化、可恢复，错误不覆盖用户结果 | 磁盘满/权限/占用/异常终止样本 |

测试包括：转换算法边界与金样、FIGlet 拼接、Unicode/ANSI/SAUCE、全部生成器/动画参数、字体回退、导出转义、CSV/JSON 往返、项目迁移、素材包、摄像头释放、3D 坏模型、性能和主流程。

输入预算覆盖解码像素、帧数、网格尺寸、公式复杂度、模型面数、字体文件、容器解压大小和 JSON 深度。HTML/SVG/代码输出转义；ANSI 只解析显示，不作为终端命令执行。
